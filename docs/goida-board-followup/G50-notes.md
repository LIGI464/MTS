# G50 · Заметки в «Подробнее» и помощь с заполнением

**Промпт для Cursor.** Добавь под блоком «Описание / Решение» в `apps/web/src/board/incident-details.tsx` отдельную секцию «Заметки». Сверь существующий слой SQLite, типизированные API чтения и записи и проверку оператора. Данные заметки — локальная запись Goida-board по ID заявки, отдельно от исходных полей ITSM.

1. Поддержи чтение и редактирование сохранённой заметки. Покажи поле, «Сохранить», состояние сохранения и ошибку с возможностью повтора. Допусти пустую заметку как явную очистку. Ограничь размер текста на клиенте и сервере. Сохраняй заметку после обновления выгрузки, перезагрузки и рестарта. Проверь, что она не переносится между заявками. Для конкурентной записи используй версию заметки и конфликт с перечитыванием, чтобы устаревший клиент не затёр изменения.
2. Добавь узкий типизированный API заметок по ID. Проверяй доступ на сервере, для записи используй действующую проверку токена оператора. Повтор запроса и ошибки не меняют экспорт, исходное «Решение», координатора или статус заявки. Определи пустое состояние для известного ID и явную ошибку для неизвестного.
3. По просьбе «Предположи решение и перенеси его в заметки» помощник готовит черновик для текущего ID. Пример — «Гипотеза: сбилось направление контура скрытия. Проверить границы контура. После корректировки повторить тест». Вставь черновик в поле заметки с предпросмотром. Оператор может отредактировать и сохранить его. Если уже есть текст, предложи добавить к нему или явно заменить, сохраняя исходное до подтверждения. Ответ модели сам по себе не даёт права записывать в БД. Без выбранного или явно указанного проверенного ID помощник запрашивает уточнение.

**Приёмка.** Проверь ручную заметку и короткую гипотезу от помощника, отмену, существующий текст, неверный токен, сетевой сбой, конфликт двух редакторов, переход A → B при ожидающем черновике и повторное открытие после рестарта.
