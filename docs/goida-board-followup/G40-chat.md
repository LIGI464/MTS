# G40 · Контекст чата, выдача аналогов и формат

**Промпт для Cursor.** Работай после G20 и G30. Точки входа — `apps/api/src/assistant/resolve.ts`, `index.ts`, общие схемы в `packages/contracts/src/assistant.ts`, `packages/analysis/src/assistant*.ts`, `apps/web/src/assistant/assistant-host.tsx`, `state.ts` и `assistant-panel.tsx`.

1. Сохрани поведение открытия из G20 и [референса](assets/assistant-idle.png). В новом чате под шапкой с контекстом заявки покажи подсказку «Задайте вопрос по заявке или по сводке пульта.» и поле «Введите сообщение». Кнопка «Отправить сообщение» активируется при непустом вводе. При открытии с пульта, из «Подробнее», переключении заявки и повторном раскрытии автоанализа нет. Уже запрошенные результаты остаются только в истории той сессии, где оператор их запросил.
2. Запускай поиск завершённых аналогов только по явной просьбе в отправленном сообщении. Положительные примеры — «Скинь, пожалуйста, похожие проблемы», «Найди аналоги этой заявки», «Были похожие завершённые инциденты?». Обычные вопросы «Что проверить?», «Сколько у нас просроченных?» и сообщение с симптомами без просьбы о поиске получают обычный ответ. Сервер проверяет намерение по текущему сообщению до поиска кандидатов или запроса к модели. Контракт ответа привязывает карточки к конкретному поисковому сообщению. В обычном ответе возвращай пустое поле `matches`, включая ответ модели или резервного режима. Учитывай просьбу с отрицанием и пустой отправленный текст. При явном запросе без выбранной заявки, ID и достаточных симптомов запроси уточнение.
3. В режиме заявки сохрани её как контекст по умолчанию. Разреши вопросы о пульте и других доступных заявках. «Сколько у нас просроченных проблем?» получает число из того же актуального серверного снимка и правила SLA, что и сводка пульта. Другой явно указанный ID можно прочитать в пределах действующего уровня доступа. Укажи, о каком наборе данных ответ. При недоступности общего снимка так и сообщи. После ответа контекст остаётся у выбранной заявки.
4. Для простого вопроса дай прямой ответ одной или двумя строками. Для диагностики используй «Кратко», «Что известно» и «Что проверить» с одним-тремя конкретными пунктами. Оформи эти блоки типизированными полями. Помечай гипотезу, подтверждённое решение бери из записи. На явный запрос аналогов показывай итог G30, причину сходства, короткие «Симптом» и «Решение» и проверенную ссылку ITSM. При пустом результате покажи одну строку «Похожих завершённых инцидентов не найдено». Соблюдай тот же формат для live и локального ответа.

**Приёмка.** При открытии проверь ноль POST и пустую историю нового чата. Проверь обычный вопрос, вопрос про весь просроченный набор и другой ID, запрос с отрицанием, явный запрос с нулём и с несколькими результатами, а также обычный вопрос после поиска. Убедись, что поиск вызван только для явных запросов и прежние карточки остаются у соответствующего сообщения. При смене заявки ответ предыдущего запроса не попадает в новый чат.
