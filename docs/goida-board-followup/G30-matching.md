# G30 · Аналоги по сути

**Промпт для Cursor.** После G20 проверь `apps/api/src/assistant/matches.ts`, `resolve.ts`, слой чтения SQLite, `packages/analysis/src/assistant.ts` и `assistant-prompts.ts`. Исправь допуск и ранжирование записей в поиске. Сохрани правило G20 о нуле автоматических запросов при открытии. Порядок вызова поиска по намерению оператора описан в G40.

1. Рассматривай последние версии завершённых инцидентов `Resolved` и `Closed`, включая архивные. Исключай исходный ID, повторы и повторно открытые заявки. Раздели доказательства по двум каналам — сходство исходной задачи/симптома и сходство конкретного выполненного решения. Для каждого результата укажи, что именно совпало, и опирайся на поля исходных записей.
2. Совпадение сущности, операции, проявления, диагностического кода или специфического действия важнее общих формулировок «заменили деталь», «не работает», «восстановили» и одинакового шаблона. Продукт и сервис усиливают содержательное совпадение. Одинаковый продукт, типовой глагол замены или два случайных слова сами по себе недостаточны. Учитывай перефразировки; если используешь модель для оценки, передавай ограниченную выборку штатному авторизованному провайдеру, проверяй ID и основания, оставь консервативный локальный режим.
3. Допускай от нуля до пяти результатов. Порог сначала, лимит после. При нуле выводи «Похожих завершённых инцидентов не найдено». Число карточек, текст ответа и доказательства берутся из одного итогового набора. Ссылки строятся по проверенным архивным ID, без вымышленных источников.

**Приёмка.** Положительные примеры — перефразированный симптом того же сбоя и одинаковое конкретное решение при различающихся заголовках. Отрицательные — инверсия поля невидимости против поломки шифр-замка, отказ кнопки другого устройства с типовым решением и HTTP 404 против HTTP 500 при разном проявлении. Проверь выдачу 0/1/нескольких результатов и стабильный порядок без добора нерелевантных карточек.
