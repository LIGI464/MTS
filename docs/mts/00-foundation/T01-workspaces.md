# T01 · Подготовь npm workspaces и команды запуска

Ты агент B00 в `setup/base`. Прочитай [ТЗ](../TZ.md) и [контракт](../CONTRACT.md). В этой задаче создай техническую основу. Бизнес-логика появится в других задачах.

**Твои пути** · корень проекта, `scripts/dev.mjs`, манифесты и пустые точки входа `apps/web`, `apps/api`, `packages/contracts`, `packages/analysis`, базовая конфигурация Vitest и Playwright.

1. Создай корневой `package.json` с `private: true`, npm workspaces `apps/*` и `packages/*`, движком Node `>=24 <25`. Пакеты назови `@mts/web`, `@mts/api`, `@mts/contracts` и `@mts/analysis`. Во всех пакетах используй ESM и TypeScript. Сервер и библиотеки компилируются `tsc` с `NodeNext`, клиент использует конфигурацию Vite.
2. Сразу внеси согласованные зависимости. Web · `react@19`, `react-dom@19`, `vite@7`, `@vitejs/plugin-react@5`, `@tanstack/react-query@5`, `@radix-ui/react-dialog@1`, `@radix-ui/react-accordion@1`, `lucide-react` и типы React 19. API · `fastify@5` и `@fastify/static@8`. Контракты · `zod@4`. Пакет анализа использует контракты и `zod@4`. В корне · `typescript@5.9`, `@types/node@24`, `tsx`, `vitest`, `@playwright/test`. Выбери совместимые релизы этих пакетов, зафиксируй версии и единственный `package-lock.json`.
3. Библиотеки экспортируют `dist/index.js` и `dist/index.d.ts`. Добавь `prep:local` и `build` с порядком из контракта. `check` и `test` используют `prep:local` на свежем checkout перед проверками. Команда `dev:web` запускает Vite в mock, `dev` поднимает API и Vite с `VITE_DATA_MODE=api`. Из `scripts/dev.mjs` запускай npm через `process.execPath` и `process.env.npm_execpath`, с раздельными аргументами и общей остановкой дочерних процессов. Это должно работать в PowerShell и Linux. Vite проксирует `/api` и `/healthz` на `127.0.0.1:8787`. Локальные порты фиксированы, конфликт порта даёт явную ошибку.
4. Подготовь `apps/api/src/start.ts` с минимальным `/healthz`, `apps/web/src/main.tsx` с минимальным React App и QueryClientProvider. Создай заготовки компонентов `shell`, `board`, `data`, `analysis`, `demo` по сигнатурам [T11](../10-web/T11-shell.md)–[T14](../10-web/T14-actions.md). `@mts/analysis` получает типизированную заглушку `createAnalyzer` в T02. TS-пути и скрипты должны позволять собрать каркас до реализации всех блоков.
5. `npm start` запускает собранный `apps/api/dist/start.js` с опциональным `.env`. Для production Fastify обслуживает `apps/web/dist` в T22. Подготовь скрипты `data:load` и `demo:step` как вызовы `node --env-file-if-exists=.env` для `apps/api/dist/demo/cli/load.js` и `apps/api/dist/demo/cli/step.js`. Исходники внутри `apps/api/src/demo/cli/**` пишет T23. CLI компилируется вместе с API и доступна в production-образе. Добавь минимальный smoke в `tests/e2e/boot.spec.ts`. Его утверждения, подходящие каркасу, остаются валидными в готовом продукте.
6. `.gitignore` покрывает `.env` и локальные env-файлы, `data/runtime/**`, `upload/**`, выданные PDF/JSON в корне, SQLite sidecar, `dist`, `node_modules` и отчёты Playwright. `.env.example` содержит имена из контракта и пустые значения ключей и токена. Параметры локального запуска используются из одного корня.

**Проверка.** `npm ci`, `npm run check`, `npm run build`. Подними `npm run dev`, проверь `/healthz` и открытие `5173`. Запусти минимальный smoke если Chromium установлен. Запиши SHA, проверенные ОС и команды.
