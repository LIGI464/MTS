# T02 · Зафиксируй типы, схемы и образцы событий

Ты агент B00. Продолжай ветку `setup/base` после T01. Прочитай [контракт v1](../CONTRACT.md). Реализуй его в `packages/contracts`. Данные для проверки берутся из локальной копии выгрузки или из синтетической фикстуры.

1. Экспортируй из `@mts/contracts` схемы `RawIncidentSchema`, `RawIncidentsSchema`, `IncidentSchema`, `SnapshotSchema`, `NoticeSchema`, `AnalysisResultSchema`, `ApiErrorSchema` и их типы. Ключи в `groups` фиксированы. Проверяй уникальность raw ID и допустимость UTC-дат при импорте. Дополнительные поля сохраняются парсером, чтобы демо могло безопасно менять исходный JSON.
2. Экспортируй `API_PREFIX`, `LOCAL_API_PORT`, `COORDINATOR_TEAM`, `STATE_LABELS`, `PRIORITY_LABELS`, `isActiveState(state)` и `getSlaState(incident, nowMs)`. Последняя функция возвращает `"normal" | "near" | "overdue" | "unknown" | "done"` строго по контракту. Используй её из T12 и T32.
3. Сделай `makeMockTimeline(nowMs)` с типом `{ initial: Snapshot; frames: Record<"critical" | "assign" | "deadline" | "resolve", Snapshot> }`. Синтетические ID · `INC000000000001` для критического сценария и `INC000000000002` для проверки второго таймера. Подготовь `Research` с указанным завершением и пустым сроком. Выставь ревизии `1–5`, последовательности событий и базовое время из аргумента. Каждый следующий снимок включает изменения предыдущего. На `assign` первый ID виден сразу в двух группах. На `resolve` он уходит из них в историю.
4. В `packages/analysis/src/index.ts` зафиксируй типы `AnalysisInput`, `PreparedAnalysis`, `Analyzer` и `AnalyzerConfig` из контракта. Временно верни валидный ответ с `source: "rules"`. Эти имена экспортируются так же после T32.
5. Зафиксируй `apps/api/src/runtime-contract.ts` и минимальные заготовки `demo/index.ts` и `analysis/index.ts` по разделу «Серверные точки стыка». Экспорты `ensureDemoData`, `registerDemoRoutes` и `registerAnalysisRoutes` заглушаются до B20, сигнатуры остаются общими. Проверь реальный импорт в локальной среде, если файл доступен · ожидаются `44` валидные записи, `5` состояний `Research` и `3` записи `Research` без срока. Справочник указывает другие ID финальных статусов, тест фиксирует использование `stateEnum`. Синтетический тест компилируется на облачном агенте только из Git.
6. Укажи владельцам веток точные имена экспортов и кейсов mock. Если меняешь сигнатуру заготовки T01, синхронно поправь её потребителя в этой же ветке и обнови `CONTRACT.md` до слияния B00.

**Проверка.** `npm run prep:local`, `npm test -- packages/contracts`, `npm run check`, `npm run build`. Подними mock и проверь, что тот может потреблять валидный `initial`. Ответь SHA и списком зафиксированных интерфейсов.
