# Техническое задание · Пульт координатора инцидентов

Хакатон Cyber Garden, кейс МТС «Инциденты в фокусе». Проект goida-code.

## Результат

Веб-дашборд для координатора массовых ИТ-инцидентов. Координатор видит четыре группы, текущее назначение и срок. Дашборд сам отражает изменения выданного JSON и сообщает об изменениях, которые требуют реакции. Анализ помогает понять суть, выбрать команду и оценить риск эскалации. Рабочая карточка открывается в ITSM, когда задан адрес системы.

Один и тот же код запускается на двух компьютерах и на VPS. На защите оба браузера могут смотреть на один и тот же публичный HTTPS-стенд. Реальные действия в ITSM остаются в ITSM. Это соответствует роли координатора и источнику данных кейса.

## Обязательные сценарии

| Код | Условие приёмки |
|---|---|
| A1 · Первый экран | При `1440×900` видны заголовки всех четырёх групп и первые карточки непустых групп. На каждой карточке читаются продукт, время регистрации, исполнитель или команда, статус и срок. Пустая группа прямо сообщает об отсутствии записей. |
| A2 · Пересечения | Наивысший активный инцидент, назначенный координаторам, виден в обеих группах с одним ID и одинаковыми данными. `Research` с заполненным `completionDate` виден в исследовании и при подходящем назначении у координаторов. |
| A3 · Критический | После сохранения валидного JSON с новым активным критическим инцидентом или повышением приоритета до `4` карточка и оповещение появляются без перезагрузки. Цель для стабильного локального стенда — до `2 с` после записи файла. |
| A4 · Назначение | Смена группы на «КЦ ИТ Координаторы Массовых Инцидентов» добавляет инцидент в группу и вызывает одно оповещение на переход. Смена исполнительной команды обновляет карточку и состав групп. |
| A5 · Решение | При завершении бывшего активного критического появляется сообщение «Критический инцидент решён». Запись пропадает из активных групп, доступна в истории и при `Research` остаётся в группе исследования. |
| A6 · Срок | Таймер обновляется каждую секунду в браузере. Изменение срока в JSON видно без перезагрузки. Для просрочки и близкого срока есть и цвет, и явный текст. Пропущенный срок отображается как «Срок не задан». |
| A7 · Анализ | По кнопке на инциденте появляется выжимка, команда с основанием и оценка риска с факторами. Стенд с codex.sale показывает источник «codex.sale». При сбое или отсутствии ключа показывает «Локальные правила». SSE и таймеры продолжают работать. |
| A8 · ITSM | С настроенным шаблоном ссылка открывает правильный ID в новой вкладке. Без шаблона доступна локальная панель инцидента со статусом «Ссылка ITSM не настроена». |
| A9 · Сбой источника | Битый, неполный или временно отсутствующий JSON сохраняет последнее валидное состояние и показывает состояние источника. После следующего валидного сохранения поток восстанавливается. |
| A10 · Повторное подключение | После обрыва SSE очередь актуализируется автоматически. Уже показанные оповещения в этой вкладке не повторяются при восстановлении. Перезапуск API с тем же томом сохраняет данные и последние события. |
| A11 · Сброс | Внизу страницы после футера раскрывается `Служебное`. В этой секции оператор подтверждает сброс, и сервер атомарно возвращает демо-набор к загруженной исходной копии. На верхнем экране кнопки сброса нет. |
| A12 · Два компьютера | Каждый ПК запускает локальную сборку по README. На VPS два браузера видят один переход по одной правке файла. В отчёте указаны SHA, распределение результатов и времена появления карточек. |
| A13 · Навигация | Верхние шторки раскрываются и закрываются, нижние разделы доступны в футере и через мобильную панель. Клавиши Tab и Esc работают, фокус возвращается к кнопке. Ссылки открывают проверенные публичные страницы, прототипные пункты явно подписаны. |

## Данные и смысл карточек

Бриф требует именно входной JSON-массив выгрузки. Живой файл `data/runtime/character_problems.json` хранит рабочие данные и передаётся на VPS через отдельный каталог. Исходный файл кейса содержит 44 записи. Пять записей в состоянии `Research` имеют дату завершения, у трёх из них дедлайн пуст. В исходном наборе встречаются приоритеты `1–3`. Из пяти записей приоритета `3` активна одна. Для демонстрации второго таймера подойдёт другой активный инцидент с меньшим приоритетом. Сценарий защиты добавляет критическое состояние с помощью реальной правки файла, поэтому демонстрация не зависит от статического наличия P1.

Правила групп берутся из [контракта](CONTRACT.md). Для закрытия используем `stateEnum`, так как значения `stateId` для `Resolved` и `Closed` в справочнике переставлены относительно самой выгрузки. Назначенная группа координаторов получает свои карточки. Если исполнитель указан, показываем человека и команду. Если группа назначена, а человека ещё нет, показываем группу с текстом «Исполнитель не назначен».

В demo-наборе дата создания и дедлайны готовятся относительно времени запуска сценария. В загруженной выгрузке МТС даты отображаются как записаны. Время представления · Европа/Москва. Дедлайн берём из поля `deadline` и выводим остаток вместе с датой в подсказке.

## Техническое решение

| Слой | Решение |
|---|---|
| Репозиторий | Один npm workspace, Node.js `24.x`, общий lockfile. Контракт типизирован Zod. |
| Web | React `19`, Vite `7`, TypeScript `5.9`, TanStack Query `5` для начального снимка и запросов, браузерный `EventSource`. CSS Modules, CSS-переменные, Radix Dialog и Accordion, Lucide для иконок. |
| API | Fastify `5` на `127.0.0.1:8787` локально. REST для снимка и действий, SSE для обновлений, `@fastify/static` для production-сборки Web. |
| Хранение | Живой JSON — источник. SQLite через `node:sqlite` хранит последний валидный снимок, ревизию и журнал событий. Один процесс API применяет изменения. Внешние редакторы работают с файлом. |
| ИИ | Серверный пакет `packages/analysis`. Встроенный `fetch`, Responses API codex.sale, Zod-проверка результата. Правила работают автономно. |
| Поставка и проверки | Docker Compose для API со встроенным статическим Web. Публикация через HTTPS reverse proxy. Vitest, Playwright Chromium, GitHub Actions. |

Локально работают Vite `5173` с proxy `/api` и Fastify `8787`. Для Cursor предусмотрен автономный mock по тому же контракту. На VPS статика, REST и события доступны на одном origin. Постоянный том содержит JSON и SQLite. Ключ модели, токен оператора и адреса хранятся в окружении сервера.

| Параметр | Решение до получения вводной |

| Формат сдачи и длительность защиты | Базовый сценарий на четыре минуты и HTTPS-ссылка плюс README. Формат жюри уточняется у команды. |

| Дизайн | Оригинальная композиция и полный набор ролей шторок по референсу. Референсом служит публичная витрина. Точное воспроизведение возможно по разрешённому МТС макету. |
