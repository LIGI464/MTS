# T41 · Astra B · Docker Compose, HTTPS-пример и CI

Ты работаешь в `feat/deploy` от SHA B00. Меняй только `deploy/**`, `.dockerignore` и `.github/workflows/mts.yml`. Сверь [контракт](../CONTRACT.md). Возьми согласованные команды B00. Прототип публикуется под нейтральным адресом проекта, по пути `/admin/incidents`.

1. Создай `deploy/Dockerfile` на `node:24-bookworm-slim` с отдельным этапом build. Контекст — корень репозитория. `npm ci`, затем `npm run build`. Перенеси в runtime production-зависимости workspaces, собранные API, Web, контракты и анализ, а также синтетический `data/demo` и `deploy/smoke.mjs` для проверки из контейнера. Убедись, что собранные команды `data:load` и `demo:step` запускаются через Node без dev-зависимостей. Используй пользователя `node`. Точка входа `npm start`, порт `8787`. Проверь реальный путь `dist/start.js`, статических ресурсов и импортов пакетов. Корневой `.dockerignore` исключает локальные данные, env, исходные вложения, отчёты и `.git`.
2. Создай `deploy/compose.yaml` с одним сервисом `dashboard`. Из хоста слушай только `127.0.0.1:` + `MTS_HOST_PORT` (8787 по умолчанию). Контейнер слушает `0.0.0.0:8787`. Монтируй `MTS_HOST_DATA_DIR` в `/app/data/runtime`. Прокидывай только согласованные env-переменные. Образ тегируй `mts-dashboard:` + `MTS_IMAGE_TAG`. `restart: unless-stopped`, healthcheck HTTP `/healthz`. Добавь метку OCI revision из тега.
3. Создай `deploy/Caddyfile.example` для существующего Caddy на хосте. Имя домена подставляется владельцем, upstream `127.0.0.1:8787`. TLS по настройкам хоста. Для маршрута `/api/v1/events` обеспечь потоковую отдачу без буферизации и проверь это smoke-тестом. Для Caddy можно использовать отдельный `reverse_proxy` с `flush_interval -1`. При другом прокси передай тот же контракт туннеля в документе.
4. Добавь `deploy/smoke.mjs`. Из аргумента base URL запроси `/healthz`, затем `/api/v1/dashboard` и первый кадр `/api/v1/events`. Убедись, что кадр пришёл до таймаута, есть четыре ключа групп и проверяемая ревизия. Заверши запрос после первого кадра. Печатай только статусы и ревизию.
5. Собери GitHub Actions на Node 24 с `npm ci`, `npm run check`, `npm test`, `npm run build` и Playwright Chromium. Браузерная проверка использует локальный синтетический набор, временный SQLite и тестовый токен. У workflow права чтения содержимого. На ветке B00 используй её boot smoke. На release ветке должны выполняться сценарии из T51.
6. Напиши `deploy/README.md`. Включи конкретные команды запуска, безопасный env вне Git, права записи пользователя контейнера на каталог данных, импорт через `docker compose run`, HTTPS, проверку SSE и откат по предыдущему тегу. Этот документ используется T42.

**Приёмка.** Образ собирается из корня и стартует без доступных секретов на синтетических данных. `node deploy/smoke.mjs http://127.0.0.1:8787` выводит успешные REST и SSE. Зафиксируй SHA и команды, которые удалось фактически выполнить. [Caddy reverse proxy](https://caddyserver.com/docs/caddyfile/directives/reverse_proxy).
