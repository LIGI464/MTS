# T22 · Astra A · Fastify, SSE и статика

Ты продолжаешь `feat/api` после T21. Твои пути · `apps/api/src/http/**`, `apps/api/src/start.ts` и HTTP-тесты. Сверь [контракт](../CONTRACT.md) и экспорт `createDashboardRuntime`. Собирай точку входа через функции регистрации, чтобы сервер, HTTP и I/O можно было тестировать отдельно.

1. Прочитай значения `HOST`, `PORT`, `MTS_DATA_DIR`, `MTS_DATA_POLL_MS` и шаблон ITSM из env, нормализуй пути от корня. Вызови `ensureDemoData(dataDir)` из `demo/index.ts` перед runtime. Опции `capabilities` вычисляй на старте. Сброс доступен при настроенном токене. Live доступен при `MTS_AI_MODE=live` и наличии ключа, модели и токена. Вызови `registerDemoRoutes(app, context)` и `registerAnalysisRoutes(app, context)`. Используй заготовки B00 до реализации T23 и T24.
2. Добавь `GET /healthz` и `GET /api/v1/dashboard`, которые читают текущий runtime. Создай общий `http/operator-token.ts` с `readBearer(header)` и `isValidOperatorToken(expected, token)`, сравнивай токены по длине и `timingSafeEqual`. Для ошибок используй `ApiError`. Логи не включают заголовки авторизации и окружение.
3. Для SSE используй `reply.hijack()`, HTTP-статус 200, заголовки из контракта и `X-Accel-Buffering: no`. Пиши `event: dashboard\ndata: <JSON>\n\n` по единой функции сериализации, первый кадр сразу. Затем подписывайся на runtime, закрывай подписку по закрытию response. Каждые 15 с отправляй ping-комментарий. При переподключении новый полный кадр даёт состояние и последние уведомления. Устрани гонку регистрации подписчика и первого кадра в том же цикле событий. Останавливай heartbeat при отключении, закрывай потоки при остановке сервера.
4. В production подключи `@fastify/static` к `apps/web/dist`. Дашборд открывается по `/` и `/admin/incidents`. Клиентские пути обслуживает index, отсутствующий `/api/*` получает JSON `404`. Избегай кеширования HTML и SSE, допускай кеширование Vite-ассетов с хешем. Локально Vite использует свой сервер. Установи допустимый размер JSON тела `8 KiB` для действий.
5. Покрой `GET /healthz`, снимок и ошибки через `app.inject`. Для SSE запусти временный порт и проверь двумя клиентами стартовый кадр, реакцию на замену файла, обновление той же ревизии при `stale` и повторное подключение. Закрой все ресурсы.

**Приёмка.** `npm test -- apps/api/tests`, `npm run check`, `npm run build`. Локальный `npm run dev:api` слушает `8787`. Дай коммит и фактические проверки.
