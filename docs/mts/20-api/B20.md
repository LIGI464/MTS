Ты Astra 6.2 A в чате №2. Ответственный человек — LIGI464 на основном ПК. Работай в облаке только с GitHub-репозиторием `LIGI464/MTS`. Начни в `feat/api` от общего SHA B00. Прочитай [ТЗ](../TZ.md) и [контракт](../CONTRACT.md). Твои пути · `apps/api/src/**`, `apps/api/tests/**` и синтетический `data/demo/**`. Зависимости, lockfile и контракт принадлежат B00.

Выполни по порядку [T21](T21-source.md), [T22](T22-http.md), [T23](T23-demo.md), [T24](T24-analysis-route.md). Сначала сделай чтение и хранение данных, затем снимок и SSE, потом демо-сброс и подключение анализа. Результат отдаётся интерфейсу по существующему контракту. Сборка ветки работает с заглушкой `@mts/analysis` из B00. Для интеграции с живой моделью потребуется ветка B30.

Пользуйся синтетическим набором из Git. Импорт выданного МТС файла через `data:load` выполняет человек при T52. В случае расхождения статусов используй `stateEnum` и канонические подписи. Все изменения в UI должны вытекать из реальных правок файла. Протестируй сбой чтения, несколько групп одного ID, оповещения, переподключение, перезапуск и токен сброса.

**Приёмка.** `npm ci`, `npm run prep:local`, `npm run check`, `npm test`, `npm run build`. Изменения `critical`, `assign`, `deadline` и `resolve` означают правку JSON, рост ревизии и новый кадр по SSE. В PR укажи SHA, тесты и способ запуска загруженного файла.
