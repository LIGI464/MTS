# T23 · Astra A · Загрузка набора, шаги и скрытый сброс

Ты продолжаешь `feat/api` после T22. Меняй `apps/api/src/demo/**`, `data/demo/**` и тесты демо. Прочитай [контракт](../CONTRACT.md). Используй согласованный runtime и проверку токена из T22.

1. Добавь синтетический `data/demo/character_problems.json` в форме той же выгрузки. Начальный P1 отсутствует. Используй как минимум два активных высоких инцидента, одну рабочую карточку у координаторов, одну запись `Research` с завершением и пустым сроком и закрытую запись для каталога команд. Стабильные ID для демонстрации · `INC000000000001` и `INC000000000002`. Наполняй живой файл на первом запуске с синтетическими датами относительно текущего времени. Дата регистрации второго демонстрационного инцидента должна быть минимум за 20 минут до старта, чтобы срок в 90 секунд попал в окно предупреждения. Базовая копия и живой файл на момент загрузки совпадают.
2. Из `demo/index.ts` экспортируй `ensureDemoData(dataDir)`. Создавай каталог, если его ещё нет. На первом старте инициализируй исходный baseline и живой файл при отсутствии обоих. Если доступен существующий живой файл, оставь его источником. Восстановление вручную удалённого файла выполняется через явный импорт или сброс, поэтому повтор запуска не перетирает входные данные.
3. `apps/api/src/demo/cli/load.ts` принимает `--file PATH`, сам читает UTF-8, проверяет массив и безопасно готовит `baseline.json` и `character_problems.json`. Пишет только в выбранный `MTS_DATA_DIR`. Проверяет оба ввода до замены. Сообщает число записей и путь, содержимое строк в лог не выводит. Импорт нового исходного набора выполнять до запуска приложения. CLI использует те же правила чтения `.env`, что и сервер.
4. `apps/api/src/demo/cli/step.ts` принимает один шаг. `critical` повышает первый активный `priorityId=3` вне группы координации до 4 и ставит «Наивысший». `assign` переводит этот активный P1 в группу координаторов. `deadline` выбирает другой активный инцидент с приоритетом 1–3, сначала по убыванию приоритета, затем по возрастанию ID. Ставит срок `now+90s`, сохраняя дату регистрации. В настоящей выгрузке активен один исходный инцидент приоритета 3, поэтому второй таймер надо уметь показывать на приоритете 2 или 1. `resolve` меняет P1 на `Resolved`, `stateId=7`, канонический `state` и `completionDate=now`. Если обязательная запись отсутствует, заверши с понятной ошибкой. Пиши соседний временный файл и переименовывай, ID и прочие поля сохраняй.
5. `registerDemoRoutes(app, context)` добавляет POST сброса. Режим включается токеном из env, валидный Bearer обязателен. Считай baseline, проверь ошибки согласно контракту и вызови `runtime.resetTo(bytes)`. Верни принятый снимок. Ошибка чтения baseline сохраняет текущий живой файл. Анализ сбрасывается подписчиком T24 по `demo.reset`.
6. Проверь synthetic шаги, успешный сброс и отказ без токена. На реальной выгрузке, если она доступна, проверь импорт 44 записей и поведение `Research`. Исходную выгрузку держи в локальном каталоге.

**Приёмка.** `npm run build`, затем `npm run data:load -- --file <путь>` и четыре `demo:step` меняют реальный файл. Таймер и оповещения обновляются. Сброс работает после перезапуска с прежним каталогом, тесты API и сборка проходят. Приложи SHA и результаты.
