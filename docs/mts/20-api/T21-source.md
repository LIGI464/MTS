# T21 · Astra A · Входной JSON, группы и журнал

Ты реализуешь ядро данных B20. Ветка `feat/api` от SHA B00. Меняй `apps/api/src/source/**`, `apps/api/src/domain/**`, `apps/api/src/store/**` и тесты этих частей. Ориентир · [контракт v1](../CONTRACT.md). Подключай `RawIncidentsSchema` и общие типы из `@mts/contracts`.

1. Нормализуй файл в записи `Incident` и приватное описание по ID. Учитывай BOM, стабильный порядок ключей и нормализованный ISO. Хеш `version` включает канонические поля и описание для ИИ. `sysId` не преобразовывать в число. Шаблон ITSM валидировать как HTTPS после подстановки. Валидация файла целиком должна завершиться до смены состояния.
2. Вычисляй четыре группы независимо. Реализуй чистый diff `previous → next` для трёх смысловых уведомлений. Порядок групп соблюдать из контракта. Массовые уведомления на первой загрузке отсутствуют. Изменение порядка raw-строк и форматирования файла не меняет ревизию.
3. Читай `character_problems.json` каждые `500 мс` по умолчанию, следующий запуск после окончания предыдущего. При изменении байтов принимай файл после двух совпавших чтений, в том числе при сохранении через переименование на Windows. При невалидном или отсутствующем файле выстави `stale` с валидным кешем или `unavailable` без него. После восстановления даже неизменившегося валидного файла отправь новый статус здоровья. У одинакового стабильного файла очередной poll не рождает кадр.
4. `node:sqlite` и `DatabaseSync`. В `dashboard.sqlite` храни текущий полноканонический снимок и описание по ID, ревизию, последний валидный момент и отдельный журнал с монотонным `seq`. В одной транзакции сохраняй снимок и уведомления. После коммита публикуй. Храни последние 50 событий для экрана. В SQLite используй монотонный `seq` и лимит 500 событий. Восстанови предыдущее состояние до первого чтения файла при старте.
5. Экспортируй `createDashboardRuntime(options: DashboardRuntimeOptions): Promise<DashboardRuntime>` из `source/index.ts` по общим типам B00. `getSnapshot()` возвращает свежий серверный момент, `getDescription(id)` — описание, `subscribe(listener)` возвращает отписку. `resetTo(bytes)` валидирует полученные байты, атомарно заменяет живой файл через соседний временный файл и фиксирует сброс в той же последовательной очереди, что и чтение. При успехе очисти старые записи ленты, сохрани монотонность `seq` и создай `demo.reset`. `close()` останавливает цикл и закрывает БД. При частичном сбое сохранения верни ошибку с сохранением последнего подтверждённого снимка.
6. Тестируй на временных путях и управляемом времени. Набор · `critical+coordinator`, `Research+coordinator` при заполненном завершении, `Resolved/Closed` по enum, null SLA, финал критического, удаление, неверный JSON, одинаковый digest, сбой восстановления, рестарт и reset с ростом seq.
