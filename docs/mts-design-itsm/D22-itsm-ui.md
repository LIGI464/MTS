# D22 · Реестр и рабочая карточка ITSM

**Промт для Astra 6.2.** Реализуй `ItsmPage({ id? })` с экспортом из `apps/web/src/itsm/`. Работай только в этой папке и её тестах. Дострой существующую тему через CSS-переменные и доступные компоненты. Прочитай [дизайн](DESIGN.md) и [HTTP-контракт](CONTRACT.md). Соседняя ветка реализует пульт и разработчиков.

1. Без ID загрузить все обращения, включая решённые и отсутствующие в текущем файле. Вывести поиск по ID/названию/продукту, метки статуса и наличия решения, явные состояния загрузки, пустого реестра, пустой выдачи и сетевой ошибки. Нажатие на номер ведёт по стабильному URL. При прямом входе карточка запрашивается у API по номеру без зависимости от выбранной строки пульта.
2. В карточке показать номер, полное описание, продукт, сервис, команду и сотрудника, статус, приоритет, время регистрации, срок и исходный текст `solution`. При пустом значении дать честную подсказку. Хронология показывает изменения и текст решения соответствующей версии. Пометь записи вне текущей выгрузки. Укажи, что это «Локальная ITSM» команды.
3. Для текущей активной заявки с правами оператора доступна форма записи решения. Вызывай сервер D21 с `expectedVersion` и `requestId`. Успех подтверждается свежим GET, решённым статусом и новой строкой журнала. При 409 сохранить введённый текст и показать, как перечитать состояние. В режиме чтения карточка и история доступны без оператора.
4. Обеспечь прямой вход/F5, «К реестру», переход на пульт, Back/Forward, поведение на 390 px и 200% масштаба. При новой ревизии обновляй реестр и открытую заявку; повторная отрисовка секундного таймера пульта не должна вызывать GET каждую секунду.

**Сдать** SHA, снимки списка и одной карточки, результаты проверки неизвестного номера и ввода решения. При наличии тестовой БД повтори открытие после рестарта API на том же каталоге. Регистрацию маршрутов и окончательный e2e выполняет D30.
