# D20 · Архив инцидентов и решений

**Промт для Astra 6.2, ветка сервера.** Реализуй на Fastify/SQLite устойчивый реестр из [контракта](CONTRACT.md). В твоей зоне `apps/api/src/{source,store,http,itsm}/`, `runtime-contract.ts`, серверные тесты и добавочные типы `packages/contracts/src/itsm.ts` с реэкспортом. Пакетные зависимости для этого блока уже есть.

1. Проследи путь данных от `readIncidentBytes` и `normalizeIncidents` до `accept` и `store.save`. Нынешняя версия карточки включает нормализованные поля и описание. Входной `solution` или неизвестный атрибут может измениться сам по себе и сейчас не вызывает обновления карточки. Обеспечь учёт таких изменений в истории ITSM и свежесть чтения из UI.
2. Добавь совместимые таблицы для записей и истории в `dashboard.sqlite` в постоянном томе. Храни исходную строку целиком. Дедуплицируй последовательные равные снимки, сравнивая данные по ID и содержимому. Появление, изменение, исчезновение и возвращение сохраняются с серверным временем. Форма ответа и направление хронологии определены в CONTRACT. Системный `sysId` остаётся строкой.
3. Включи архивирование в существующую транзакцию принятия валидного массива. При старте старой базы заполни архив из файла даже при одинаковом снимке пульта. Повреждённый файл, повторный poll, перестановка строк, перезапуск и нажатие F5 не создают ложных изменений. При сбросе восстанови текущий набор и сохрани историю прежних заявок. Публичная лента из 50 событий и архив на полный срок жизни проекта служат разным задачам.
4. Реализуй GET реестра и карточки, правильные 404 и `Cache-Control: no-store`. Покажи в карточке различие между пустым решением и заполненным решением активной записи. Существующий внешний шаблон ссылки и v1 Snapshot остаются совместимы. Текст произвольного поля в UI выводится обычным текстом.
5. В Vitest проверь чистую и прежнюю БД, первоначальный импорт, повторное чтение, правку только `solution`, A → B → A, удаление из файла, возврат, неизвестный ID и восстановление при невалидном JSON. На синтетике проверь большой строковый ID и неизвестное вложенное поле.

**Сдать** SHA, примеры GET без секретов и команду тестов с выводом. При локально доступных оригиналах сверить 44 номера и исходные решения; без оригиналов прогонять синтетические тесты и явно назвать набор.
