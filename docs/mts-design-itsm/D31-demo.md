# D31 · Защита с одного ПК

**Промт для Cursor и памятка LIGI464.** Проведи репетицию на одном origin и одном постоянном тестовом каталоге. По брифу обязательны автоматическая реакция на файл, четыре группы, переход в ITSM, оповещения и польза ИИ. Второго компьютера для этой репетиции не нужно.

## Подготовка

1. На локальной машине с Node 24 собери рабочую ветку. В примере PowerShell создаётся отдельный каталог под прогон. Переменные в примере задаются только в этом терминале; оставь его открытым на время показа.

   ```powershell
   npm ci
   npm run build
   $env:MTS_DATA_DIR = Join-Path $env:TEMP ("mts-demo-" + [guid]::NewGuid().ToString("N"))
   $env:MTS_AI_MODE = "rules"
   $env:MTS_OPERATOR_TOKEN = [guid]::NewGuid().ToString("N")
   Set-Clipboard -Value $env:MTS_OPERATOR_TOKEN
   npm start
   ```

   При необходимости перед `npm start` выполни `npm run data:load -- --file "C:\MTS-case\character_problems.json"`, подставив свой путь. `incidents_attributes.json` нужен для проверки полей. Встроенный набор работает сразу. Для живого ИИ используй уже настроенный демонстрационный стенд с серверным ключом.

2. В окне A открой `http://127.0.0.1:8787/admin/incidents`. В окне B открой `http://127.0.0.1:8787/admin/developers` и введи токен из буфера. На VPS оба окна должны указывать на один и тот же HTTPS-стенд с интеграционной сборкой. Используй отдельный тестовый том для публичной демонстрации записи/сброса.

## Четыре минуты для показа

| Время | Действие | Что увидит жюри |
|---|---|---|
| 0:00–0:30 | Окно A, обзор пульта | Четыре очереди, читаемые продукт, время, статус, команда и SLA. Пример Research может оставаться у координаторов. |
| 0:30–1:00 | В B нажать «Добавить критический», записать новый ID | В A появляется новый инцидент и одно оповещение без F5. Живой JSON увеличивается на одну запись. |
| 1:00–1:40 | В B назначить этот ID координаторам и поставить срок через 90 секунд | В A тот же номер в двух группах. Обе карточки показывают одинаковое назначение и новый срок. |
| 1:40–2:20 | В A открыть детали и запустить ИИ | Видны выжимка, рекомендуемая команда, риск, факторы и фактический источник. Таймер продолжает идти. |
| 2:20–3:20 | Из A нажать «В ITSM». В новой вкладке сверить ID и ввести решение | Открывается постоянный URL, видно исходное описание. После сохранения A сигнализирует о решении, в ITSM появляется новая версия с введённым текстом. |
| 3:20–4:00 | Перезагрузить карточку, открыть реестр и найти номер | Решение и хронология доступны по той же ссылке. Показать ранее загруженную заявку и её `solution`. |

Отдельно перед защитой останови локальный `npm start` через Ctrl+C и запусти снова в том же терминале. Снова открой ссылку на решённую заявку, сравни номер, текст и количество версий. В этом же изолированном прогоне проверь ручное сохранение изменённого JSON, ошибку формата и возврат валидной версии. В конце можно выполнить подтверждаемый сброс демо и открыть прежнюю запись из архива. Как только операторский токен вставлен, очисти буфер обмена.

**Сдать** SHA, тип набора, скрин пульта и карточки на тестовых данных, ID, фактическую задержку «запись → видимое оповещение» (ориентир до 2 с локально), источник ИИ и результат повторного открытия после перезапуска. В отчёте отдельно указать, какой origin действительно проверили.
