# Редизайн пульта МТС, тестовые сценарии и локальная ITSM

Исполнитель — **LIGI464, один ПК, два чата**. Cursor ведёт интерфейс. Astra 6.2 ведёт данные, сервер и часть экранов по готовому контракту. На защите один человек открывает на одном компьютере два окна одного стенда.

Рабочая исходная версия — `release/cybergarden`, коммит `d23acbed7117f209c69716a79df31fdf5fd4cc28`. В момент подготовки ветка `main` содержала только основу. Исторические B00–T52 описывают предыдущий этап. Для этого обновления начни здесь.

## Что получится

| Куда зайти | Что можно сделать |
|---|---|
| `/admin/incidents` и `/` | Увидеть четыре очереди, срок и назначение. С карточки открыть заявку в ITSM одним кликом или посмотреть детали и ИИ-анализ. |
| `/admin/developers` | Добавить новый критический инцидент, повысить приоритет существующего, назначить координаторов, изменить срок, записать решение и воспроизвести сценарий перед жюри. |
| `/itsm/incidents` | Найти инцидент по номеру, продукту или заголовку, в том числе после решения или исчезновения из рабочей выгрузки. |
| `/itsm/incidents/:id` | Прочитать исходное описание и решение, увидеть историю изменений, внести итог решения с правами оператора. Прямая ссылка работает после перезагрузки. |

## Первый запуск на своём ПК

1. Открой PowerShell в клоне `LIGI464/MTS`. Подготовь Node.js 24 и Git. Исходные `character_problems.json` и `incidents_attributes.json` держи вне Git. Синтетический набор уже лежит в репозитории. Он подходит для разработки без ключа ИИ и без VPS.
2. Подготовь рабочую линию с этой папкой. Команды ниже можно выполнить из своего клона с любыми незакоммиченными правками в его рабочем каталоге — новые работы идут в соседних каталогах. При повторном входе открой ранее созданные каталоги, их список покажет `git worktree list`.

   ```powershell
   git fetch origin
   git worktree add -b design/integration ../MTS-integration origin/docs/mts-design-itsm
   cd ../MTS-integration
   git rev-parse HEAD
   ```

3. **Первое сообщение в Cursor** (открой папку `MTS-integration`).

   > Открой `docs/mts-design-itsm/D00-start.md` и выполни промт целиком на текущем HEAD. Я LIGI464, работаю с одного ПК. Верни исходный SHA, результаты проверок и две готовые строки запуска для Cursor и Astra 6.2.

4. D00 даёт общий SHA. Из `MTS-integration` подготовь рабочие ветки. Публикация ветки делает ту же базу доступной облачной Astra.

   ```powershell
   git worktree add -b design/ui ../MTS-ui HEAD
   git worktree add -b design/service ../MTS-service HEAD
   git -C ../MTS-service push -u origin design/service
   ```

5. Открой `MTS-ui` в Cursor. Для локальной Astra используй `MTS-service`. Для облачной Astra выбери GitHub `LIGI464/MTS`, ветку `design/service`. Передавай следующий файл по таблице. Каждый агент работает в своей копии. Общий lockfile принадлежит Cursor в D10.

## В каком порядке выдавать промты

| Волна | Cursor | Astra 6.2 | Что должно быть готово перед стартом |
|---|---|---|---|
| 0 | [D00 · Проверить исходную сборку](D00-start.md) | — | Рабочий релиз и эта папка |
| 1 | [D10 · Подключить Granat и тему](D10-granat.md) | [D20 · Архив ITSM и чтение](D20-archive.md) | Обе ветки от SHA из D00. Эти два задания независимы |
| 2 | [D11 · Оболочка, доска, детали и ИИ](D11-dashboard.md) | [D21 · Сценарии и запись решения](D21-mutations.md) | На каждой стороне завершён предыдущий собственный блок |
| 3 | [D12 · Страница разработчика](D12-developers.md) | [D22 · Реестр и карточка ITSM](D22-itsm-ui.md) | D11 в UI-ветке, D21 в серверной. У D12 и D22 разные папки. Порядок между этими двумя работами свободный |
| 4 | [D30 · Соединить и прогнать проверки](D30-integration.md) | Ревью исходных решений и истории на интеграционном SHA | Оба SHA доступны LIGI464 |
| 5 | [D31 · Репетиция с двух окон](D31-demo.md) | — | Интеграционная сборка из D30 |

Если запускаешь один чат за раз, выполняй D00 → D10 → D20 → D11 → D21 → D12 → D22 → D30 → D31. Перед каждым заданием выбирай соответствующую ветку. В облаке попроси Astra запушить результат своей ветки и вернуть SHA. D30 забирает оба результата. При ожидании доступа к Granat серверная дорожка и проверка рабочих сценариев продолжаются.

## Что требуется от LIGI464

| Когда | Действие | Что передать агенту или проверить самому |
|---|---|---|
| До D10 | Найти комплект МТС для участников | Ссылка на официальный Web UI kit, registry с именем и версией пакета или выданный архив. Если выдали Figma — ссылка на библиотеку с правом чтения, экспорт токенов и доступные иконки/шрифты. Учётные данные настраиваются локально. |
| До D20 | Выбрать данные | Для CI достаточно `data/demo`. Для сверки оригинала дай локальному Cursor пути к двум JSON. Облачной Astra достаточно описания полей из [контракта](CONTRACT.md) и синтетических фикстур. |
| Между волнами | Принимать изменения | Прочитай небольшой diff по заявленным путям, результат команды и SHA. Если одна проверка упала, передай её вывод тому же агенту. |
| До D31 | Выбрать один origin и подготовить оператора | Локального `npm start` достаточно. Для показа с VPS используй тестовый экземпляр с постоянным томом и ту же сборку. Токен вводится в поле оператора. |
| В конце | Проверить три вещи руками | Новый ID виден в обоих окнах, переход ITSM ведёт именно в этот ID, сохранённое решение доступно по старой ссылке после перезапуска. |

Каждый промт можно отдавать одной фразой: «Работай от текущего SHA согласованной ветки. Прочитай `docs/mts-design-itsm/<имя файла>` и выполни его. Сдай SHA, изменённые пути и фактические результаты». Имена файлов есть в таблице.
