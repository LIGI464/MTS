# P40 · Приёмка

Работай на ветке P30. Проверь связь с исходным коммитом `a16db4ae5a087000ddb81e81df30ba4634eca71a` и наличие результатов P00–P30. На Node 24 выполни `npm ci`, `npm run check`, `npm test`, `npm run build` и `npm run test:e2e`. Используй подготовленный Chromium или штатный Playwright Chromium, если его нужно установить. Укажи конкретную ошибку для каждой непроведённой проверки. Принимай локальную облачную сборку. Для прогона используй временный синтетический экспорт и мок живого провайдера.

| Сценарий | Подтверждение |
| --- | --- |
| Расчёт видит весь набор | Заявка за пределами видимой области попадает на первое место, если её основание важнее. Фильтр на экране не ограничивает кандидатов. Обоснования проверяются по принятым данным. |
| Режимы расчёта | Проверь результат модели, локальные правила, пустой результат, недоступность провайдера и безопасный ответ после сброса. Ревизия, повторы, статус и версия заявки согласованы со снимком. |
| Описания в очередях | Заявка вне ленты получает короткий фактический абзац под названием без подписи об ИИ. У той же версии в очереди и секции SLA одинаковый текст. После обновления версии виден актуальный текст, а при недоступной модели — описание из текущей заявки или сообщение об отсутствии симптомов. ID, статус, приоритет, координатор, SLA и действия видны. Технические поля открываются через «Подробнее». |
| Лента на пульте | Порядок карточек соответствует общей выдаче. На карточке видны проблема и причина срочности. Нажатие на рекомендацию приводит к её карточке в очереди и автоматически открывает соответствующие детали. |
| Все семь переходов из сводки | Проверь критический, координаторский, оба SLA и три обычных приоритета. Скролл указывает конкретную карточку. Красная рамка держится после ожидания и следующего перехода. Открытие деталей снимает подсветку только у просмотренной цели. |
| Сроки | Обе секции изначально свёрнуты. Клик по одному из SLA-сегментов раскрывает нужную секцию и подсвечивает цель там. Проверь дубликат ID в приоритетной очереди, пустой список и переход из near в overdue. |
| Критические | В первом пригодном снимке есть активный критический. Рамка светится. Новый инцидент добавляет счётчик «Непросмотрено» в правом верхнем углу и акцент на стрелке. После просмотра последнего нового инцидента рамка активна до исчезновения последнего критического. |
| Журнал «События» | Добавь события через тестовый JSON и проверь список, типы, счётчик, фильтр, закрепление, повторное подключение и переход в детали. Всплывающие карточки отсутствуют на обеих страницах пульта. Отдельно проверь критическое, координаторское, разрешение и сброс. |
| Звук и данные ITSM | Подтверди правила звука через тестовый `AudioContext`, в том числе повторную доставку и тихий SLA. Пульт читает координатора из ITSM и поддерживает поиск, фильтры и стандартные действия деталей. [D30](../mts-dashboard-review/D30-unread-and-sound.md) |

## Визуальные кадры

Сними широкий пульт с лентой и критическим индикатором, нижнюю сетку с раскрытым SLA и стойкой подсветкой низкого или среднего приоритета, «Подробнее» после клика из ленты и отдельную карточку очереди с новым описанием. Проверь 1440×900, 1280×720 и 390×844. Проверь Tab, Enter, Escape, программный фокус, `prefers-reduced-motion`, загрузку местных WOFF2 и отсутствие горизонтального скролла страницы. [Четыре референса](DESIGN.md)
