## Команды

Проверки прошли в локальной облачной сборке на Node `24.22.1` с npm `11.9.0` и системным Chromium `156.0.8078.79`. Для Fastify использовали временную копию демоэкспорта и управляемый HTTP-ответ провайдера. Для теста локального экспорта собрали временный набор из 44 записей штатной синтетической фикстуры. Браузерные тесты запускались с временной конфигурацией Playwright, которая указывала `/usr/bin/chromium` и каталог результатов.

## Проверенные сценарии

| Сценарий | Наблюдение |
| --- | --- |
| Полный набор и порядок | В тесте `FAR-IMPACT` стоит в конце входной выгрузки и выходит на первое место за счёт подтверждённой блокировки оплаты при низком приоритете ITSM. В контрольном демопрогоне аналогичная `INC-P10-20` заняла первое место среди 25 записей. Поиск в пульте сохраняется и не меняет состав ленты. |
| Режимы расчёта | Подтверждены ответ модели, локальные правила, пустой снимок и отказ провайдера. Посторонний ID, дубликат, неверная версия и вымышленная цитата отклонены. Повторные запросы используют один расчёт. Переход SLA пересчитывает порядок без повторного вызова недоступного провайдера до окончания паузы. При смене версии и сбросе во время расчёта API возвращает `409 PRIORITIES_STALE`. |
| Описания в очередях | `INC000000000002` получила краткое описание даже вне ленты P10. Обычная и SLA-карточка одной версии показывают одинаковый абзац. При смене версии используется текст нового снимка уже во время запроса. Для заявки без фактов показано «В заявке нет описания симптомов». ID, статус, приоритет, координатор, SLA и оба действия доступны. Исходные поля проверены в деталях. |
| Лента | Порядок совпал с серверным на обоих маршрутах. На широком экране видны четыре карточки. На мобильном лента прокручивается внутри своей области. Нажатие и Enter открывают точные детали, Escape возвращает фокус в ленту. При обновлении сохраняются пригодные рекомендации, при сетевом сбое виден статус ошибки. |
| Наведение | Красная обводка толщиной 1 px появилась по очереди на каждом из пяти сегментов и исчезла после ухода курсора. Проверены наклон, перенос между рядами и фокус после Tab. |
| Семь переходов и сроки | Исходно обе секции SLA закрыты. Переход раскрывает нужную, а ручной заголовок переключает состояние, включая пустую секцию. Проверены семь категорий, адресное раскрытие под фильтром, точный экземпляр при дубле ID, переход near → overdue и сохранение подсветки после ожидания и следующего перехода. «Подробнее» снимает только соответствующую подсветку и отмечает конкретное поступление просмотренным. |
| Критическая сводка | Первый снимок с активными критическими дал устойчивую рамку без новой метки. Новая запись добавила «Непросмотрено» и акцент стрелки. После открытия деталей метка и акцент погасли, рамка сохранилась при активных заявках. |
| Журнал «События» | На `/` и `/admin/incidents` в двух контекстах проверены критическое поступление, назначение координаторам, разрешение и демосброс. Проверены счётчик, порядок и типы записей, московское время, фильтр, закрепление, переход в детали и переподключение без повторной записи. Всплывающий слой и кнопки «Закрыть оповещение» отсутствуют. |
| Звук | Тестовый `AudioContext` зафиксировал четыре сигнала в сценарии с новыми критическими и отдельным изменением координатора. Одно обновление с критическим поступлением и назначением дало один сигнал. Повтор SSE, переподключение, обычные приоритеты, переходы SLA, чтение, разрешение и сброс не добавили звука. Изменение при выключенном звуке не проигралось после включения. |
| Данные ITSM и доступность | Проверены координатор из выгрузки, поиск, фильтры, ссылка «В ITSM» и клавиатурные действия Tab, Enter и Escape. При `prefers-reduced-motion` подсветка различима. На 1440×900, 1280×720 и 390×844 ширина страницы совпала с шириной окна. На каждой ширине загружены шесть WOFF2 с адреса приложения. |

## Контрольные кадры

1. `INC-SYN-104` занимает первое место. Видны четыре рекомендации, критический индикатор и наведение на высокий приоритет. [Пульт с лентой](evidence/P40/P40-01-priority-feed.png)
2. Нажатие первой рекомендации открыло `INC-SYN-104` с её рангом и тем же обоснованием. [Детали](evidence/P40/P40-02-priority-details.png)
3. Переходы в низкий приоритет и просроченный SLA сохранили две красные рамки. Обычная копия `INC000000000003` в среднем приоритете сохранила свой контур. [Очереди и SLA](evidence/P40/P40-03-persistent-selection.png)
4. Абзац `INC000000000003` находится под заголовком. Координатор, срок и действия видны. [Карточка с описанием](evidence/P40/P40-04-incident-description.png)

### Воспроизведение

- Запустите собранный пульт на временной копии [демоэкспорта](../../data/demo/character_problems.json) через [тестовый стенд](../../tests/e2e/support/harness.ts) в режиме `live-ok`. Для `INC000000000002` задайте срок примерно через 12 минут, для `INC000000000003` задайте срок около 18 минут назад. Начало у обоих сроков должно отстоять от текущего времени достаточно, чтобы `getSlaState` считал первый срок близким.
- Добавьте через `writeLive` низкоприоритетную `INC-SYN-401` с подтверждённым сбоем поиска и покупок. После загрузки пульта добавьте критическую `INC-SYN-104` со сбоем авторизации и координатором. Наведите курсор на «Высокий приоритет», затем откройте первую рекомендацию.
- Закройте детали и нажмите «Низкий приоритет», затем «Просрочены». Сохраняются рамки `INC-SYN-401` в её очереди и `INC000000000003` в секции SLA. Для отдельного кадра используйте версию `INC000000000003` из средней очереди.
