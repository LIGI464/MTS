Добавь целевые сценарии для непокрытых регрессий в существующие наборы.

## Сценарии приёмки

| Сценарий | Наблюдаемое поведение |
| --- | --- |
| Пустая валидная выгрузка | На `/admin/incidents` есть два верхних блока «Критические» и «У координаторов» с нулями. Под ними одна панель с пятью сегментами в порядке «Срок близко», «Просрочены», «Высокий приоритет», «Средний приоритет», «Низкий приоритет». Сегменты разделены диагональными чертами. Очереди показывают понятное пустое состояние. Рамка, точки и звуковой сигнал отсутствуют. |
| Три критических в исходном снимке | Счётчик сразу показывает 3. После первого снимка блок остаётся спокойным и звук не играет. |
| Прибыл четвёртый критический | После внешней записи в временный JSON счётчик показывает 4. Новый непросмотренный ID включает красное свечение по периметру верхнего блока. Рабочая лента отражает поступление события один раз. Звуковой сигнал подтверждается при включённом звуке. |
| Переход к критическому инциденту | Нажми верхний блок с клавиатуры и мышью. Пульт прокручивается к карточке полученного ID, включая случай со скрывающим её фильтром. Именно эта карточка дважды подсвечивается красным. Когда событие просмотрено, счётчик остаётся 4. Если остался другой непросмотренный критический, рамка остаётся и следующий переход доступен. |
| Событие в некритической категории | Для каждого из пяти сегментов подтверди точку, попадание ID в ожидаемую категорию по действующим правилам SLA и приоритета, переход к нужной карточке и отсутствие звука. Целый сегмент и карточка без критического статуса сохраняют штатное оформление. Если один ID совпадает с несколькими категориями, проверь связь индикаторов с событием и снятие только соответствующего непросмотренного состояния. |
| Событие «У координаторов» | При поступлении подтверждённого координаторского события появляется точка в верхнем блоке и играет звук, если он включён. Переход ведёт к той же заявке в отдельной очереди «У координаторов». Её состав и счётчик согласованы с `snapshot.groups.coordinator`, включая пограничные статусы, которые этот контракт поддерживает. |
| Один ID подходит для двух звуковых категорий | Новый критический и координаторское событие в одном обновлении обрабатываются по правилам предыдущего блока. Проверь отсутствие повторного сигнала для одного поступления, корректные индикаторы обеих групп и отсутствие повторного воспроизведения при SSE-повторе. |
| Пульт переподключается | При повторной доставке снимка, повторе события и ререндере не возникают дубликаты в ленте, точках или звуке. Выключенный звук, исходная загрузка и его включение после старых событий не воспроизводят накопленное. Ошибка чтения и восстановление проходят по штатному сценарию источника. |
| Источник назначения и защита записи | Задай в временном JSON известного координатора и проверь одинаковое имя в очереди и деталях. Измени назначение непосредственно в выгрузке и проверь новое значение после штатного обновления и перезапуска. Исходное значение JSON имеет приоритет над старым локальным назначением. Контролы назначения и смены отсутствуют в пульте, реестре и сценариях. Старая команда записи, включая прямой запрос с валидными правами, не меняет JSON, локальную проекцию или историю. |
| Остальные входы в приложение | Проверь `/`, `/admin/incidents`, `/admin/developers`, `/itsm/incidents` и прямую ссылку `/itsm/incidents/:id` после перезагрузки. Проверь фильтры, переход «В ITSM», детали, правила ИИ, изменение срока и запись решения по действующим контрактам. |

## Визуальная сверка

1. При `1680×1040` сохрани два скриншота рабочего пульта. Сравни их со спецификацией и обоими PNG из [DESIGN.md](DESIGN.md). Первый сделай на валидной пустой выгрузке. Второй сделай до открытия новых событий, когда видны красное свечение блока «Критические», точка в «У координаторов» и точки в нижней панели для присутствующих событий. Используй управляемое состояние анимации, чтобы на втором кадре индикаторы были видны.
2. Проверь при `1440×900`, `1280×720` и `390×844`, что заголовки и числа не обрезаются, доступен порядок пяти сегментов, прокрутка приводит к карточке и верхняя шапка её не перекрывает. Проверь Tab, Enter, Escape в деталях и `prefers-reduced-motion`. Сокращённое движение сохраняет видимый результат перехода.
3. В собранном приложении проверь загрузку шрифтов из `apps/web/src/styles/fonts/` и действующие семейства в `apps/web/src/styles/theme.css`. Русские заголовки, основной текст, числовые значения и кнопки используют предусмотренные веткой семейства и начертания. Проверь отсутствие ошибок загрузки из консоли и штатную читаемость объёмных заголовков заявок.

**Сдать** SHA базы и проверенного результата, список изменённых файлов, фактические результаты команд и сценариев, два скриншота с путями или вложениями текущего запуска и ID заявок для воспроизведения. Для проверки звука укажи, наблюдался ли управляемый вызов аудио в браузерном тесте. Если что-то упало, исправь причину в пределах этих блоков и повтори затронутые команды.
