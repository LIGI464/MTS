# D30 · Непросмотренные инциденты, переходы и звук

Продолжи реализацию в `LIGI464/MTS` на рабочей ветке, основанной на `fix/dashboard-review`. Базовый снимок этого комплекта — `5aa37dc9d81c391a865b01ed5453612e8b664b77`. Перед началом проверь результат D10 (координатор из JSON ITSM) и D20 (компоновка сводки и очередь «У координаторов»).

Работай с кодом, тестами, шрифтами и референсами из рабочей копии. Открой [визуальную спецификацию](DESIGN.md), [пустой пульт](references/dashboard-empty.png) и [пульт с непросмотренными событиями](references/dashboard-unread.png). Второй кадр показывает яркую фазу подсветки до клика. Результат блока — работа уведомлений по правилам ниже на странице пульта.

## События и непросмотренность

1. Различай общий счётчик инцидентов, количество непросмотренных событий и факт звукового сигнала. Счётчик категории рассчитывается из её состава с уникальными ID. Просмотр события меняет признак непросмотренности.
2. Первый пригодный снимок фиксирует исходные ID, состав категорий, SLA и уже полученные номера событий. Существующая история остаётся видимой в журнале. Стартовая загрузка, повторный снимок и повторная доставка SSE сами по себе не дают подсветку или звук. При краткой потере связи опирайся на последнюю пригодную базу и сохраняй ожидающие просмотра события в текущем сеансе пульта.
3. Привязывай каждое оповещение к ID инцидента, категории и устойчивому ключу события. Используй `Notice.seq` для серверных событий. Для новых ID и переходов SLA используй факт изменения по сравнению с предыдущим состоянием, чтобы повтор рендера, тик таймера или повтор снимка не создавали дубликатов. Новое независимое событие по уже известному ID может снова потребовать внимания.
4. Определи видимые сигналы по состоянию:
   - «Критические» — новое `critical.new`. Оно может относиться как к новой заявке, так и к заявке, впервые попавшей в критический состав после базового снимка.
   - «У координаторов» — `coordinator.assigned` либо `coordinator.changed` из обновления ITSM. Цель перехода для этой карточки должна быть доступна в очереди «У координаторов». Если изменение относится к инциденту вне состава очереди, сохраняй запись в журнале и используй правило звука ниже.
   - Высокий, средний и низкий приоритеты — новые инциденты соответствующего приоритета. Используй то же определение состава, что для счётчиков.
   - «Срок близко» и «Просрочены» — попадание активной заявки в соответствующее состояние SLA после базового снимка. Учитывай новую заявку с таким SLA и переход существующей заявки по времени или после обновления срока. Пока SLA остаётся в том же состоянии, сигнал считается одним событием. При выходе из состояния учти актуальность цели, при новом входе снова можно подать сигнал.
5. Одно поступление может относиться к нескольким категориям. Покажи сигналы во всех подходящих блоках и свяжи их с одним просмотром того же поступления. Если по той же заявке позже пришло отдельное событие, оно остаётся непросмотренным до собственного подтверждения. Порядок «самое свежее первым» определи детерминированно, используя время и последовательность события.
6. Журнал хранит историю, включая решённые инциденты и служебные события. Само открытие журнала может обновить его собственный индикатор при наличии такого поведения, а сигналы сводки остаются до просмотра конкретной цели. Ограничение длины видимого журнала не должно удалять ожидающую просмотра доступную цель. Сброс демонабора делает новый снимок исходной базой, очищает старые сигналы и отменяет незавершённый переход.

## Как выглядят сигналы

- В обычном состоянии карточка «Критические» выглядит как на кадре пустого пульта. При наличии хотя бы одного непросмотренного критического инцидента пульсируют красная рамка и мягкое свечение по всему периметру блока. Используй красный цвет и другие токены темы из `fix/dashboard-review`. Счётчик и название читаются в обеих фазах. Пульсация возвращается к обычной рамке после просмотра последнего доступного критического события.
- «У координаторов» и пять сегментов нижней полосы получают только компактную мигающую красную точку в своей предусмотренной позиции. Сохрани обычную рамку и текущие индикаторы состояния данных. В качестве доступного имени добавь информацию о непросмотренном событии так, чтобы скринридер не объявлял её на каждую фазу анимации.
- В режиме `prefers-reduced-motion: reduce` покажи устойчивую рамку или точку. Подсветка и состояние должны читаться при отключённых анимациях.
- На разных ширинах точка и рамка не перекрывают названия, счётчики и соседние действия. Для новых тихих уведомлений используется точка в их категории и запись в журнале.

## Переход к нужному инциденту

1. Сделай две карточки сводки и пять сегментов доступными действиями для мыши и клавиатуры. При наличии непросмотренных событий выбери самое свежее доступное в нажатой категории. При их отсутствии веди к заголовку соответствующей очереди или списку по выбранному SLA.
2. Найди карточку по ID и категории внутри нужной очереди. Один инцидент может отображаться в нескольких очередях. Нажатие «У координаторов» ведёт в одноимённую очередь, нажатие «Критические» — в критическую. Для SLA и обычных приоритетов используй соответствующие видимые списки и фильтры D20.
3. Если запрос поиска или фильтр скрывает карточку, раскрой её в правильном контексте через существующую фильтрацию. Сохрани прочий контекст оператора насколько позволяет выбранный переход. Дождись, пока нужная карточка отрисуется, и прокрути страницу или внутренний список так, чтобы карточка была видна и её не закрывала шапка. При навигации с клавиатуры перенеси фокус на целевую карточку или её доступное действие. При включённом reduced motion переход мгновенный.
4. На критической карточке после прокрутки воспроизведи **ровно два** красных импульса, затем верни обычное оформление. Для некритических блоков сигнал остаётся точкой до подтверждения просмотра. В режиме reduced motion вместо двух импульсов используй статический акцент на цели. Перерисовка и повторный снимок сами по себе не перезапускают анимацию.
5. Подтверди просмотр только после успешного показа точной карточки или открытия её деталей. Один переход не гасит сигналы по другим заявкам. Если цель исчезла из актуального списка, оставь событие в журнале и перейди к следующей доступной цели либо к заголовку очереди. Переход подтверждает просмотр только при показе карточки. Обрабатывай новый клик и сброс так, чтобы отложенное завершение старой прокрутки не подтвердило чужую цель.

## Правила звука

| Событие | Когда звучит |
| --- | --- |
| `critical.new` | Один сигнал при включённом звуке |
| `coordinator.assigned`, `coordinator.changed` из JSON ITSM | Один сигнал при включённом звуке |
| Новый обычный приоритет, новое состояние SLA | Тихо |
| `critical.resolved`, демосброс, чтение журнала, прокрутка | Тихо |

Классифицируй звук по типам событий. Один инцидент, ставший одновременно критическим и поступивший к координаторам в одном обновлении, даёт один сигнал, хотя могут включиться рамка и точка. Отдельное последующее изменение по тому же ID может дать новый сигнал. Сохрани активацию WebAudio через действие пользователя и состояние переключателя «Звук оповещений». Включение звука влияет на будущие события. Повторная доставка, переподключение, открытие деталей и сообщения, накопленные до включения, не воспроизводятся. Для звука используй реализацию из ветки.

## Проверка и сдача

Обнови тесты `apps/web/src/operations/tests/activity.test.ts` и `tests/e2e/operations.spec.ts` по затронутому поведению. Для звука используй существующий тестовый `AudioContext` и проверяй число сыгранных сигналов. Для SLA используй управляемое время. Для анимации проверяй целевую карточку, момент запуска после перехода, число итераций и режим reduced motion.

| Сценарий | Ожидаемый результат |
| --- | --- |
| Исходно пустой пульт | Нулевые счётчики, обычные рамки, точек и звука нет |
| Первый снимок содержит три прежних критических | Счётчик 3, журнал доступен, блок спокойно оформлен и не звучит |
| Добавили четвёртый критический | Счётчик 4, рамка пульсирует, один звук при включённом переключателе |
| Клик по критическому блоку | Видна точная новая карточка, два импульса, после чтения счётчик 4 |
| Две непросмотренные заявки в одном блоке | Первый переход подтверждает одну, для второй сигнал сохраняется |
| Появилась заявка высокого, среднего или низкого приоритета | Точка только в соответствующем сегменте и иных подходящих категориях, звука от приоритета нет |
| SLA переходит в «Срок близко», затем «Просрочены» | Каждый вход учитывается один раз, звука нет |
| Назначение или изменение из JSON ITSM | Для цели в очереди координаторов появляется точка, при включённом звуке один сигнал |
| Один ID одновременно входит в критические и у координаторов | Рамка и точка возможны одновременно, звук один, клик ведёт в выбранную очередь |
| Цель скрыта фильтром или находится глубоко во вложенном списке | Открывается точная карточка, отметка прочтения относится к этому событию |
| Повтор снимка или SSE, переподключение, демосброс | Повторы не создают звук, сброс устанавливает базу без входных сигналов |
| Звук выключен и затем включён, в браузере включён reduced motion | История не проигрывается, следующий разрешённый сигнал звучит, переходы и статические индикаторы доступны |

Прогони `npm run check`, `npm test` и затронутые сценарии Playwright через `npm run test:e2e`. Сдай изменённые пути, результаты команд и список проверенных сценариев. Если среда ограничила запуск проверки, укажи конкретную ошибку и те проверки, которые удалось выполнить.
