# D20 · Компоновка дашборда и очередь координаторов

**Задание для облачного GPT в LIGI464/MTS.** Продолжи рабочую ветку после D10. Реализуй новую сводку и очередь на существующем экране / и /admin/incidents. Источники дизайна — [спецификация](DESIGN.md) и исходный пульт из fix/dashboard-review на 5aa37dc9d81c391a865b01ed5453612e8b664b77.

## 1. Входные точки и тема

Открой apps/web/src/App.tsx, operations/dashboard.tsx, operations/dashboard.module.css, operations/queue-summary.ts, operations/filters.tsx и board/incident-board.tsx с его CSS. Проверь тему styles/theme.css и имеющиеся компоненты шапки, фильтров и карточек. Пути после App.tsx относительны к apps/web/src/.

Подключай шесть файлов через действующие @font-face в apps/web/src/styles/theme.css:

| Тема | Файлы | Применение |
|---|---|---|
| MTS Compact | MTSCompact-Regular.woff2, MTSCompact-Medium.woff2, MTSCompact-Bold.woff2 | --font-sans, основной текст, кнопки, подписи |
| MTS Wide | MTSWide-Medium.woff2, MTSWide-Bold.woff2 | --font-display, заголовки и счётчики |
| MTS Text | MTSText-Regular.woff2 | --font-text, соответствующие текстовые роли ветки |

Все файлы лежат в apps/web/src/styles/fonts/. За внешний вид отвечают те же токены, поверхности, интервалы, скругления и значки, что использует ветка. Для визуальной сверки используй [пустой](references/dashboard-empty.png) и [заполненный](references/dashboard-unread.png) кадры со штатными шрифтами ветки.

## 2. Сводка

1. После заголовка и статуса источника размести две белые карточки. Слева «Критические», справа «У координаторов». На широком экране колонки равны. У каждой карточки есть заголовок, общий счётчик и доступное действие перехода к своей очереди. У критической есть состояние красной рамки, у координаторской — место для точки. Эти состояния подключаются в D30.
2. Сразу под карточками помести одну непрерывную панель. У неё общий белый фон, один внешний контур и четыре внутренних диагональных разделителя. Слева направо идут «Срок близко», «Просрочены», «Высокий приоритет», «Средний приоритет», «Низкий приоритет». У каждого сегмента свой счётчик, семантическая кнопка и свободное место справа вверху под точку. Разделители визуальные. Метка и точка не перекрываются.
3. После панели размести заголовок очередей и существующие поиск и фильтры, затем списки заявок. Переиспользуй карточки и группы приоритетов из board/model.ts. Добавь отдельную «У координаторов» рядом с критической группой. В карточке показывай имя из D10 с меткой ITSM.
4. На узком экране сохраняй порядок групп, перенос подписей, равномерную читаемую геометрию и видимый клавиатурный фокус. Плотность интерфейса и мобильное поведение сверяй с исходной веткой и [DESIGN.md](DESIGN.md).

## 3. Правила данных

- Сводка считает уникальные инциденты по ID из здорового либо последнего принятого снимка, как в приложении. Для критических используй активную группу critical. Для SLA используй getSlaState и действующую границу «близко». Высокий, средний и низкий используют действующие приоритеты 3, 2 и 1 в активном наборе. Разница счётчиков между исходным и фильтрованным списком должна быть объяснима интерфейсом.
- Членство в «У координаторов» определяется через snapshot.groups.coordinator, которое вычисляет контракт packages/contracts/src/groups.ts. Группа включает заявки команды координаторов активного статуса или Research. Одни и те же ID используй для общего счётчика, карточек отдельной очереди и разрешения цели перехода. Наличие персонального имени является самостоятельным полем из ITSM.
- При исходном состоянии фильтров показывай все записи группы координаторов, включая Research. Поиск и явно выбранные фильтры могут сужать видимый набор, после сброса группа возвращается целиком. Счётчик заголовка видимой очереди может отражать её отфильтрованный список. Счётчик сводки описывает весь набор категории.
- Инцидент может одновременно удовлетворять критической группе, SLA и группе координаторов. Отображай его один раз внутри каждой очереди. На DOM-уровне обеспечь стабильную возможность выбрать нужную карточку по ID и группе. Для SLA-сегмента цель может находиться в существующей приоритетной очереди.
- В здоровом пустом снимке показывай сводку с нулями и пустые состояния очередей. Для загрузки, устаревшего снимка и недоступного источника продолжай использовать соответствующие состояния из App.tsx.

## 4. Проверить и сдать

Проверь порядок двух карточек и пяти сегментов, общую рамку полосы, подключение локальных WOFF2 и точное размещение поиска. Проверь нули на пустом снимке, отсутствие двойного подсчёта внутри группы, Research в очереди координаторов и пересечение по ID с другим приоритетом. Отдельно пройди размеры 1440×900, 1280×720 и 390×844. Укажи пути изменений и фактический результат проверок. Затем продолжи D30.
