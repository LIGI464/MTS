# D10 · Координатор из ITSM

Ты облачный GPT с доступом к репозиторию `LIGI464/MTS`. Продолжи рабочую ветку после подготовки по D00. Базовый снимок приложения — `fix/dashboard-review` на коммите `5aa37dc9d81c391a865b01ed5453612e8b664b77`. Все файлы, команды и демоданные бери из репозитория. Используй временный каталог данных для тестов. Для них подходят синтетические строки из `data/demo/character_problems.json` и существующие фабрики в тестах.

Сделай персональное назначение координатора доступным для чтения. Пульт, карточка, детали и читающие маршруты API должны получать актуальное имя из экспорта ITSM. Следующие блоки используют тот же контракт и события обновления.

## Источник и правила

- Источник — `MTS_DATA_DIR/character_problems.json`. Начни с `apps/api/src/source/input.ts`, `apps/api/src/source/coordinators.ts` и `apps/api/src/source/index.ts`.
- Переиспользуй сопоставление из `exportedName`. По исходной записи `assignedGroupName` должен совпадать с `COORDINATOR_TEAM`, а `assignedEmployee` содержать имя после удаления пробелов по краям. Пустое или отсутствующее имя означает отсутствие подтверждённого персонального назначения. В интерфейсе покажи «Координатор не указан в ITSM».
- Опциональный `coordinators.json` сопоставляет имя из экспорта с идентификатором. Имя, которого нет в справочнике, читается по действующему правилу `exportedCoordinator` со стабильным ID. Оставь доступным чтение справочника для фильтра.
- Персональное имя и членство в очереди — независимые данные. Заявка команды координаторов с активным статусом по `isActiveState` или со статусом `Research` может входить в `snapshot.groups.coordinator` даже при пустом `assignedEmployee`. Сохрани существующее правило группировки. Очередь добавляется в D20.

## API и ранее сохранённые данные

1. Исправь `projectCoordinators` и вызовы в runtime. Сейчас `assignments.get(incident.id)` может перекрыть имя из файла. Устрани этот приоритет и путь записи нового ручного назначения. Используй проекцию ITSM последовательно для снимка и архивного представления. Контракты чтения должны принимать исходные данные с именем и записи без него.
2. Проверь запуск с существующим `dashboard.sqlite`. Кэшированный `snapshot.incidents` и текущая архивная запись могут содержать старое ручное имя. Для текущего представления восстанови имя из последней принятой сырой записи, если внешний файл недоступен. Если подтверждённой сырой записи нет, отображай отсутствие подтверждённого назначения. Проверь список и детали через `apps/api/src/store/index.ts` и `apps/api/src/store/itsm.ts`. Сохрани историю, старые записи и использованные идентификаторы версий. Подмена устаревшей проекции при запуске сама по себе не должна создавать событие обновления из ITSM.
3. При реальном изменении имени в новой принятой выгрузке обнови текущий снимок, детали и список. Проверь доставку `coordinator.changed` текущим потоком. Вход в команду по данным ITSM продолжает порождать `coordinator.assigned` по правилам `apps/api/src/domain/index.ts`. Одинаковая выгрузка не создаёт нового события.
4. Закрой маршрут `POST /api/v1/itsm/incidents/:id/coordinator` в `apps/api/src/itsm/index.ts` и серверную команду `set-coordinator` в `apps/api/src/itsm/mutation.ts` и `apps/api/src/source/index.ts`. Прямой запрос с действующим тестовым токеном должен получить ответ об ошибке и оставить назначение, версию заявки и историю без записи. Найди связанные места по `AssignCoordinator`, `assignCoordinator` и `itsm_coordinator_assignments`. Сохрани данные старой таблицы, если она уже существует. Оставь рабочими штатные чтение, импорт выгрузки, разрешение инцидента и несвязанные операции.
5. Проверь сценарий `assign` в `/api/v1/dev/scenarios`, который сейчас может изменить `assignedGroupName` и `assignedEmployee` в рабочем файле. Поступление в команду демонстрируй обновлением копии экспорта или существующим изолированным мок-сценарием. В рабочем режиме с ITSM назначение через интерфейс и команды приложения должно быть недоступно. Оставленный сценарий на синтетических данных подпиши как имитацию поступления обновления ITSM.

## Пульт и карточки

- Убери «Назначить координатора» и «Сменить координатора». Проверь цепочку `apps/web/src/App.tsx` → `board/incident-board.tsx` / `board/incident-details.tsx` → `board/coordinator-form.tsx`. Проверь вызов `assign` в `apps/web/src/data/incidents.ts` и его мок в `apps/web/src/data/incident-fixtures.ts`. Удали код и стили, оставшиеся без вызовов.
- Покажи «Координатор» и имя рядом с пометкой ITSM в существующих карточке и деталях. Имя исполнителя оставь отдельным полем. Для старых версий без явного `coordinator` проверь `incidentCoordinator` в `apps/web/src/board/model.ts`. Читаемый резерв для старого снимка допустим, когда он эквивалентен правилу проекции из выгрузки. Явное отсутствие назначения должно сохраняться.
- Переиспользуй запрос справочника и действующие фильтры для чтения. Открытие деталей, ссылка ITSM, фокус и возврат к карточке должны работать после удаления режима назначения.

Обнови связанные сценарии `apps/api/tests/mutations.test.ts` и `tests/e2e/d30.spec.ts`, где тесты напрямую пользуются удалённым назначением. Замени такие шаги изменением тестового экспорта и проверкой результата.

| Случай | Ожидаемый результат |
| --- | --- |
| Экспорт содержит координатора А, в старой SQLite сохранено ручное имя Б | Пульт, чтение списка и деталей показывают А. Запись истории доступна |
| Перезапуск со старой базой, файл временно недоступен либо некорректен | Показывается последнее подтверждённое в принятой записи назначение. Состояние источника остаётся видимым |
| В новой выгрузке имя А сменилось на В | Пульт, детали и API читают В. Поток получает одно настоящее `coordinator.changed` |
| У записи команды координаторов пустое имя | Поле показывает «Координатор не указан в ITSM». Группировка опирается на команду и статус |
| Справочник отсутствует или имя из файла в нём не найдено | Имя из экспорта отображается со стабильным ID |
| Устаревший POST отправлен с рабочим токеном | Ошибка. Экспорт, SQLite и события не получают записи назначения |
| Оператор открывает обычную карточку | Имя читается из ITSM. Интерфейс содержит рабочие детали и фильтры без формы назначения |

Запусти проверку типов, тесты изменённых модулей и доступный сценарий Playwright. В отчёте укажи SHA, изменённые файлы, как проверен запуск со старой базой, и фактический результат каждой команды.
