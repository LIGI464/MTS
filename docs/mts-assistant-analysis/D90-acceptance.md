# D90 · Приёмка «Помощника МТС»

**Промт для облачного GPT.** Работай в `LIGI464/MTS` после D60, D70 и D80. Возьми фактический SHA принятого результата D40 из задания запуска. Проверь, что он в истории текущей рабочей ветки и что в ней есть результаты всех трёх блоков. Прочитай их контракты и diff. Для полного прогона достаточно репозитория, временных синтетических выгрузок и штатного тестового окружения.

## Запуск проверок

1. Из корня выполни `git status --short --branch`, `git rev-parse HEAD`, `git merge-base --is-ancestor <принятый-SHA-D40> HEAD` и `node -v`. Используй Node.js 24 по корневому `package.json`.
2. Выполни `npm ci`, `npm run check`, `npm test`, `npm run build`, `npm run test:e2e`. Используй доступный браузер Playwright. При отсутствии Chromium проверь возможность штатного `npx playwright install chromium`. Для каждого пропуска приведи фактическую причину.
3. Для интеграционного прогона используй `tests/e2e/support/harness.ts`, синтетический `data/demo/character_problems.json` и временный каталог тестового инстанса. Сверь нормализацию на действующих фикстурах. Для загрузки архива используй штатный поток импорта из `tests/e2e/d30.spec.ts` и `apps/api/tests/import.test.ts`. Проверяй серийный сценарий на собранном приложении с живым тестовым API.
4. Запусти целевые проверки D60–D80 и существующие `apps/api/tests/analysis.test.ts`, `packages/analysis/tests/analyzer.test.ts`, `apps/web/src/analysis/tests/state.test.ts`, `tests/e2e/operations.spec.ts`. Добавь недостающие регрессионные сценарии в действующие наборы. Для живого провайдера используй его тестовый двойник. Подтверди режим правил без ключа. В отчёте явно укажи, какой режим использовался в каждом прогоне.

## Данные, ответы и переходы в ITSM

| Сценарий | Проверяемый результат |

Сделай первую загрузку через проверку и подтверждение импорта. Следующим импортом убери один из завершённых ID из активной выгрузки. После штатного обновления и перезапуска проверь, что в архиве сохраняется исходное решение и поиск находит этот ID по правилам D60. |
| Допуск и порядок | Для запроса по контекстной заявке и общего запроса проверь релевантные завершённые ID по правилам D60. Исключи `WorkInProgress`, `Research`, повторно открытый случай, контекстную заявку и нерелевантную запись. Для релевантной завершённой записи без решения проверь отсутствие выдуманного решения. При совпадении записи в рабочем наборе и архиве проверь один результат на ID и согласованную версию. Повтор запроса на тех же данных выдаёт тот же порядок. |

Открой ссылку, проверь нужный ID и перезагрузи страницу. Используй маршруты или настроенный шаблон, которые предусмотрены действующим контрактом ITSM. |
| Совпадений нет | Для запроса вне подготовленного архива верни явное состояние без совпадений. Проверь, что интерфейс показывает его и остаётся доступен для следующего вопроса. Ссылки и решения появляются только у подтверждённых результатов. |
| Сбой провайдера | Проведи успешный ответ с тестовым провайдером, затем тайм-аут или ошибку и повтор. | API | Проверь согласованный в D70 контракт `POST /api/v1/assistant/chat` для запроса без ID и с существующим ID, а также для невалидного тела и неизвестного ID. Сопоставь ответ с клиентским типом. Проверь после завершения запросов, что поиск оставляет исходную выгрузку, назначение и состояние заявок прежними. |

## Входы и поведение панели

1. С закрытыми деталями на пульте нажми «Помощник МТС». Появляется только чат с предложением указать номер или симптомы. В шапке нет выбранного ID, окно «Подробнее» не открывается, автоматического запроса нет. Введи вопрос или номер, проверь ответ внутри чата и переход в ITSM по ссылке. Открытие деталей требует явного действия оператора. Сверни и раскрой чат, проверь сохранение общего разговора и черновика.
2. Открой «Подробнее» заявки A. Убедись, что в карточке отсутствует «ИИ-анализ», SLA виден и помощник пока закрыт. Нажми ту же нижнюю кнопку «Помощник МТС». В шапке чата видны ID и заголовок A, передан один автоматический запрос. На широком экране именно детали A остаются рядом слева. Дождись архивных карточек и отправь уточнение. Сверни чат, закрой детали и нажми помощника на пульте. Откроется общий чат без привязки A. Затем повтори запуск с открытой заявкой B и проверь, что запоздалый ответ по A не попадает в чат B.
3. Сверни чат и прокрути пульт, затем прокрути длинные детали с открытой карточкой. Закреплённая кнопка остаётся доступной в обоих случаях. Раскрой чат и проверь, что нижняя кнопка скрыта и исключена из порядка Tab. Чат занимает доступную высоту с обычным нижним отступом. Внутри доступны независимая прокрутка истории, поле ввода и отправка.
4. Открой чат, сверни его из шапки и повторно открой с вернувшейся нижней кнопки. Проверь те же действия через Escape и клавиатуру, порядок Escape для нескольких слоёв и возврат фокуса к исходной кнопке. Проверь Tab, Enter, длинные русские строки, индикацию ожидания и повтор после сбоя. Для `prefers-reduced-motion` проверь смену состояния без длинного перехода. На узком экране проверь компоновку каждого состояния в пределах окна без горизонтальной прокрутки страницы.
